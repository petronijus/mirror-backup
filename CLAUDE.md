# Mirror Backup for GNOME

Linux rsync backup system: `scripts/backup-sync` (bash) + systemd user timers +
GTK4/libadwaita app with a command line (`src/backup_monitor/`, run as
`mirror-backup`) + panels: GNOME Shell extension (`gnome-extension/`) and the
Omarchy bar widget (`omarchy-plugin/`). `~/.config/backup-sync/jobs.json` is
the source of truth; the app generates systemd units from it. See README for
architecture, especially "Several machines, one set of jobs".

## Where state lives — keep bash and Python in step

- Job state: `<destination>/.mirror-backup/` (status.json, history.jsonl,
  backup.log, deferred) — shared by every machine/OS mounting the destination.
- Per boot: `$XDG_RUNTIME_DIR/backup-sync/` (queue.lock, <job>.pid/.progress).
- `src/backup_monitor/paths.py` and the top of `scripts/backup-sync` resolve
  the same paths; change them together.
- The rules for reading a status (unavailable / interrupted / dead / live, by
  boot id + PID) live once, in `models/job.py:read_status`. The panels do not
  re-implement them: they read `mirror-backup status --json` (snapshot.py).
- Units are generated by `units.py`; only units with its MARKER line are ever
  removed, and replaced units go to the trash (they may hold hand edits).

## Look on Omarchy

`desktop_theme.py` (GTK-free, tested) turns the current Omarchy theme into a
libadwaita stylesheet; `desktop_style.py` applies it above the app's own CSS
and reloads on theme switches. GNOME is untouched. Test windows open on the
user's live desktop — prefer the CSS parse check and unit tests over
screenshots, and never leave a test window where a click could save a job.

## Tests

`tests/run.sh` — everything; must pass before a commit. The Python tests are
stdlib `unittest` (no pytest), the widget's `Model.js` runs under node,
`tests/test_backup_sync.sh` drives the real script against temp dirs.

## Repo conventions (public repo)

- Conventional commits: `feat:` / `fix:` / `chore:` / `docs:` / `refactor:`.
- Releases are cut with the `repo-release` skill; config in `.release.yml`.
  Never tag or edit CHANGELOG.md manually. App version lives in
  `src/backup_monitor/__init__.py` (`APP_VERSION`); `metadata.json` `version`
  is the separate e.g.o integer — bump when extension content changes.
  `omarchy-plugin/manifest.json` has its own `version`.
- Private overlay: `private/` (gitignored) = clone of
  `petronijus/mirror-backup-gnome-private` — Petr's jobs in
  `private/configs/backup-sync/` (jobs.json + excludes). `install.sh` links
  `~/.config/backup-sync` to it, so Ubuntu and Omarchy on petronijus-PC (which
  share `~/Documents`) run the same jobs.
  Bootstrap: `git clone git@github.com:petronijus/mirror-backup-gnome-private.git private`
